# LLM Knowledge Wiki

一个持续维护的个人知识系统：原始资料保留出处，知识页提炼可复用结论，灵感与项目记录各自归档。

## 从这里开始

- [知识索引](<Wiki/Wiki 索引.md>)：按主题浏览已整理文章。
- [每日哲学](<Wiki/哲学索引.md>)：按日期阅读哲学观点，查看原典出处与思考问题。
- [原始资料](Raw/index.md)：查看来源与整理结果，获取采集模板。
- [项目索引](<Projects/项目索引.md>)：查看具体项目的执行记录。
- [灵感索引](<Ideas/灵感索引.md>)：记录个人想法、感悟与复盘。
- [附件索引](<Attachments/附件索引.md>)：查看本地图片与引用位置。
- [Dashboard](dashboard.md)：Obsidian Apex Dashboard 的日常入口。

## 目录与归属

| 位置 | 保存什么 |
| --- | --- |
| `Raw/` | 原始文章、摘录和来源信息 |
| `Wiki/` | 来源总结、主题知识、方法和参考规范 |
| `Ideas/` | 自己的想法、感悟、思考和复盘 |
| `Projects/` | 具体项目的计划、执行记录、验证结果和待办 |
| `Attachments/` | 本地图片等附件 |
| `AGENTS.md` | 知识库整理与查询规则 |

`Wiki/` 目前采用平铺文件加主题索引，沿用已有文章名。项目相关记录按项目建子目录。笔记正文使用 Obsidian `[[双向链接]]`，本页使用相对 Markdown 链接，方便直接浏览仓库。

## 新资料如何进入知识库

1. 将资料放入 `Raw/`，保留标题、作者、来源链接与采集日期。
2. 在 `Wiki/` 创建来源总结，区分原文观点与整理者推论。
3. 优先补充已有主题页；没有对应主题时再新建。
4. 添加有意义的交叉链接，并更新资料清单和相关索引。
5. 最后核对本地链接与附件，列出新增和更新文件。

查询时先读 `Wiki/`，需要原文证据时再回看 `Raw/`。完整规则见 [AGENTS.md](AGENTS.md)。

## 本地配置与版本管理

`.obsidian/` 保存 Obsidian 配置。内容文件、附件、通用配置和命名工作区可纳入版本管理；当前会话布局、`.smart-env/` 索引缓存、Dashboard 自动备份及本地环境变量文件已加入 Git 忽略规则。插件的 `data.json` 可能保存密钥、会话或位置，因此全部只保留在本机，不纳入提交；换机后需重新配置这些插件设置。
